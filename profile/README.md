InfraTales publishes AWS infrastructure work under an explicit public-repo model. The goal is not to maximize repo count or marketing language. The goal is to keep the public organization honest, reproducible, and reviewable.

Not every public repo is production-ready. Some repos are runnable implementations. Others are architecture case studies or learning examples. Incomplete work should stay private or be archived.

## Repository Types

Every project repo must fit exactly one type defined in [REPO_TYPES.md](https://github.com/InfraTales/.github/blob/main/REPO_TYPES.md):

- **Production Reference Implementation**
- **Architecture Case Study**
- **Learning Example**
- **Internal / Draft**

Public repos must declare their type near the top of the README.

## Status Model

Every public repo must also declare one status:

- **Experimental**
- **Stable**
- **Maintained**
- **Archived**

Draft work should remain private.

## Public Quality Standard

InfraTales uses explicit review documents instead of blanket claims:

- [PUBLIC_REPO_STANDARD.md](https://github.com/InfraTales/.github/blob/main/PUBLIC_REPO_STANDARD.md)
- [REPO_REVIEW_SCORECARD.md](https://github.com/InfraTales/.github/blob/main/REPO_REVIEW_SCORECARD.md)
- [PUBLIC_RELEASE_CHECKLIST.md](https://github.com/InfraTales/.github/blob/main/PUBLIC_RELEASE_CHECKLIST.md)
- [LICENSE_POLICY.md](https://github.com/InfraTales/.github/blob/main/LICENSE_POLICY.md)
- [ORG_CLEANUP_PLAN.md](https://github.com/InfraTales/.github/blob/main/ORG_CLEANUP_PLAN.md)

These documents are the source of truth for what InfraTales repos are allowed to claim publicly.

## Licensing

Licensing is repository-specific and must match the checked-in `LICENSE`, README language, badges, and package metadata.

If a repo uses the current custom InfraTales license, it should be described as **source-available**, not MIT or Apache licensed.

## What To Expect From Public Repos

- Runnable repos should have a documented and verified first-run path.
- Case studies should say clearly that they are case studies, not turnkey systems.
- Learning examples should stay narrow and educational.
- Anything incomplete, inconsistent, or misleading should be reclassified, archived, or made private.
